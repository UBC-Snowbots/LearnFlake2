# CameraPipeline — 2026-11-07

Implemented headless `python -m orion_bench.live_demo` with local TorchScript pose and classifier files or their artifact directories. Required flags: `--pose`, `--classifier`, `--source` (nonnegative camera index or local video path), and `--output-dir`; optional `--device cpu|cuda` (default cpu), `--max-frames`, and `--classifier-manifest`. The adjacent classifier `model_manifest.json` is used automatically when present. Missing manifest means no threshold decision; a supplied or adjacent manifest must contain `source.validation_threshold`. Requested unavailable CUDA is an error. Existing nonempty output directories are rejected.

The 640-square RGB letterbox goes to the raw `[1,56,8400]` pose export; confidence filtering and IoU NMS precede conversion to original-image coordinates. Greedy IoU matching assigns short-lived track IDs; each track has causal 15 Hz held-sample windows of 48 image-normalized COCO-17 `(x,y,confidence)` observations. Long observation gaps reset the window; classifier output is softmax class 1. Results are diagnostic scores, not validated gestures.

Outputs: `overlay.mp4`, `frames.jsonl` (timestamp, tracks, normalized keypoints, scores and per-frame latency), and `summary.json` (status, timing and effective processed FPS). Failed runs retain diagnostics and return nonzero. Video timestamps use frame index / reported FPS; camera timestamps use monotonic capture time. Output video uses source/nominal FPS, so camera playback is not a wall-clock timing record; JSON timestamps are authoritative. Variable-frame-rate files are approximated with nominal FPS; file decode failures after at least one frame cannot be distinguished reliably from EOF by OpenCV. Tracking can swap IDs in occlusion or crossings; sampling holds past detections and resets on gaps, and neither live accuracy nor Jetson performance has been established. Only trusted local TorchScript files should be loaded.

No inference, tests, builds, or formatters were run by its author. The integration owner should exercise CPU real-video input, camera failure handling, unavailable CUDA, and output artifacts; real Jetson and webcam use remain unverified.
